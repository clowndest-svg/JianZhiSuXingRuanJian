## 第五批（2026-10-16 03:55 上线）：本地模型、长期记忆、假数据总根、通知与使用情况

### 这一批最大的一条：身体数据有六处会被系统编造

上一轮那条静态判据只检查“含数字的元素文本有没有被 JS 绑定”，`value=` 属性它根本没看，于是漏过一整类。
这次查出来的链条是六处，任何一处都足以让一个从没填过年龄的人带着“26 岁 / 165cm / 140 斤”去算 BMR 与 TDEE：

| 位置 | 原来写的 |
| --- | --- |
| `index.html` | 7 个输入框带 `value=` 预填：周期 138.4 斤 / 76cm、档案 26 岁 / 165 / 140 / 120、注册 26 岁 |
| `app.js` 注册 | `parseInt(...) || 26 / || 165 / || 140` |
| `app.js` 档案回填 | `p.age || 26`、`p.weightJin || 140`、`p.targetWeightJin || 120` |
| `app.js` 档案保存 | 同上，且目标体重留空时写 `(weightJin - 15)` |
| `server.py` `RegisterReq` | 字段默认值 `age=26`、`height=165.0`、`weight_jin=140.0`、`target_weight_jin=120.0` |
| `server.py` `profiles` 建表 | 列默认值 `DEFAULT 26 / 165.0 / 140.0 / 120.0` |

现在：默认值全部拿掉，`_body_or_400()` 在**开库之前**校验（缺项与超范围都返回 400 并报出是哪一项），
前端四个入口全部改成“空着/离谱就拒”，界面只剩 placeholder 提示（提示语不会被提交）。
注册页的目标体重仍按 −12% 估，但只出现在 placeholder 里并写明“仅供参考，要自己填”。

同批挖出两条：① `syncTargetWeightPlaceholder()` 在 HTML 的 `oninput` 里被调用，`app.js` 里从来没有这个函数——
档案体重框每敲一个字符抛一次 ReferenceError（模板层的东西逻辑审查看不见，正是“界面说的 vs 代码做的”那类）；
② 旧版 `register()` 写库中途报错时**不关连接**，连接带着未提交事务留在进程里，实测 3 个活连接中 2 个在事务中，
后续每次写都 `database is locked`。

### AI 顾问 v2：五层顺序，以及“模型没跑”的三种说法

`/api/ask` 现在依次是 **本人真实数据 → 长期记忆 → 本机知识库 → 联网检索 → 本机小模型合成**。

- **搜索词必须改写**。上一版把整句口语直接扔进必应，问“中午吃多了晚上怎么自适应补救”拿回百度百科
  《中午（汉语词语）》。实测根因是必应咬住查询串的**第一个词**：首位是“喝”“黑”这类单字就给字典页。
  在这台服务器上对比过四种写法，结论是领域词“减脂”一律打头，不是“句子里有了就不加”。
  判据现在钉的是这个不变量（`rewrote.startswith(减脂)`、句末语气词不进查询串、单字动词不开头）。
- **每用户长期记忆**：新表 `ai_memory`，只在用户明说「记住…」时写入，可「忘记所有」清空；
  按 `user_id` 隔离，并用两个账号实测过“别人查不到你的”这条。
- **联网内容进知识库**：新表 `kb_entries`，同问题 7 天内复用、不再重复抓网，
  答案尾部写明“这条来自本机知识库，某日查证过，不是实时结果”。
- **本机模型**：llama.cpp `b11669` CPU 版 + `Qwen2.5-0.5B-Instruct-q8_0`，systemd `qingsu-llama.service`，
  只监听 `127.0.0.1:8081`（`ss` 实测）。实测数：常驻 RSS 752 MB，生成 35.7~44.9 tok/s，
  一条回答 0.5~2.0 秒，就绪 2 秒；跑模型期间轻塑首页仍 200、可用内存还剩 2778 MB。
  对比过 q4_k_m（601 MB，但照着资料收敛更差），按实测取 q8_0。提示词禁止它补资料里没有的数字。
- **失败要说清是哪种失败**。模型侧三态出口：真合成 → `source=web_model`；模型回“不够” → 摘录并写
  “本机模型认为这些资料不足以回答”；调不通 → 摘录并写“本机模型未运行。原因：<异常名>”。
  这三条文案与 `source` 都有判据钉着——我在这一批里就写错过一次，兜底一律标 `web_model`，
  等于把摘录冒充模型合成。

## 第六批（2026-10-16 05:10 上线）：双引擎 AI、Redis、新图标、动作示意动画、自动更新、网页独占功能

### 1. 双引擎 AI：手机本地优先、服务器兜底，记忆与知识库两端共用

`/api/ask` 之外新增三个端点：`/api/ai/status`（三态健康）、`/api/ai/context`（本人真实摘要 + 长期记忆 + 知识库要点）、`/api/ai/record`（把本机引擎查到的东西写回**同一个** `kb_entries`）。客户端 `askAnyEngine()` 的决策是：`auto` 下本地在线就用本地、本地任何一步不成即降级服务器；**只选本地**时本地挂了要报错，不许偷偷用服务器冒充；**只选服务器**时连 127.0.0.1 都不探。两个引擎读的是服务器那一份记忆与知识库，所以换引擎不会让用户之前说过的话失效。

**为什么 APK 里没有内嵌模型权重**（用户原话是「内嵌进 apk」）：三个实测数——0.5B 最小可用档 q8_0 是 675 MB；这台服务器公网下行实测 0.33 MB/s，内嵌等于下载 34 分钟；而厂商（截图那台手机的「超级守护」）已经在管控未备案 APK 的安装，包再翻 100 倍只会更糟。所以权重不进包，本地引擎改为连接用户自己手机上已监听的 OpenAI 兼容端点（默认 `127.0.0.1:8081`，可改），界面给「测本地」按钮与三态显示。**这台机器没有装 NDK**（`android-sdk` 下只有 build-tools / platforms / platform-tools），Android 原生推理二进制我无法在此构建，所以「手机本地模型」这一条交付的是客户端引擎与协议，没有交付随包运行的模型——这是没做到，不是做完了没测。

**AI 问答全量测试**：`_ai_matrix.py` 跑在服务器上，打真实后端、真实模型、真实必应，29 项，含**真停真起** `qingsu-llama.service` 来验兜底路径。测完按 `LIKE 'aitest%'` 清干净并复核 `users=2`。

### 2. Redis 上了，RabbitMQ 按实测不上

Redis 走 Docker（容器 `qingsu-redis`，只绑 `127.0.0.1:6379`，`--maxmemory 64mb`），**实测 RSS 12.38 MiB**，整机可用内存只从 2744 降到 2730。用在三处：问答 / 公开接口 / 登录失败的限流（重启不清零、多进程共享）、公开大屏 8 秒缓存、知识库读缓存。零新依赖——用 stdlib 直写 RESP 协议，没装 `redis-py`。

RabbitMQ 也真装真跑了一遍再删：**空载 RSS 147.6 MiB**，可用内存 2730 → 2553，且它自己把内存高水位设到 1462 MiB。结论是不装——本项目是单进程 FastAPI + SQLite，**没有任何消费者**，队列没有下游就是纯缓冲，还多一个故障域。真要异步任务，先用 Redis 有序集合做延迟队列。

这一项踩到两个真问题，都已修：① `bytearray(字符串)` 不带编码会直接 `TypeError`，第一次调用就失败，再被 30 秒冷却短路，整层 Redis 看起来像「挂了」而状态接口只说 `down` 不说为什么——现在失败原因记进 `_redis_last_err` 并由 `/api/ai/status` 的 `redis_why` 报出。② 限流搬到 Redis 之后，回归台里那 10 句 `_ask_hits.clear()` 变成空操作（清的是已经没人用的字典），于是 5 条知识库判据被限流挡掉，看起来像功能坏了。教训：**把状态挪走时，所有清状态的测试语句都要跟着挪**，否则测试在悄悄骗人。

**基线 78/104 = 75.0%**，26 条失败逐条看完，其中 21 条是产品问题、5 条是我判分口径太严。修掉的产品问题：

## 安全（2026-10-16 第三批加固）










| 项目 | 之前 | 现在 |
| --- | --- | --- |
| 口令存储 | 无盐 SHA-256（可被彩虹表与 GPU 爆破） | 每用户随机盐 + `scrypt(n=16384,r=8,p=1)`；老账号在**下次成功登录时透明升级**，无需重置 |
| 登录态 | 令牌原文存库 | 只存令牌的 SHA-256，拖库拿不到可用令牌。**代价：两个老账号的旧登录态当场失效，需重登一次** |
| 公开大屏 | `/api/public/dashboard?username=X` 无鉴权，用户名可枚举 | 必须带 `?k=<share_secret>`；密钥在注册时生成、老账号启动时回填。**无密钥与用户不存在返回完全相同的响应**，页面也不再回显用户名 |
| 口令爆破 | 无限制 | 同 IP+用户名 15 分钟内失败 5 次即 429（实测第 5 次起返回 429） |
| 公开接口滥用 | 无限制 | 按 IP 60 次/分限流；`/api/ask` 另按用户 12 次/分 |
| CORS | `allow_origins=["*"]` 且 `allow_credentials=True` | 关掉 credentials（前端只用 Authorization 头，不用 cookie） |
| Android | `allowBackup="true"`，登录态可随系统备份导出 | `allowBackup="false"` + `fullBackupContent="false"` |

**没解决的一条，别误会**：站点仍是 **HTTP 明文**，没有域名也就没法上可信证书。上面这些是"拖库了也拿不到明文口令和可用令牌"，但**正在输入密码那一刻仍能被同网段观察到**。要真正堵掉需要域名 + 证书（或至少让 App 走 HTTPS 反代），那是基础设施决定，不是代码能自己变出来的。

## 功能与它的边界

### 打卡与热量账本
四张流水表：饮食、空腹体重、训练、饮水。用户填什么就存什么，没有自动补录。

- 饮食热量：不填 `cal` 时走**两级确定性估算**——先把菜名按 `, 、 ; 空格` 切开，每段在内置的 **68 条常见菜品成分表**（`FOOD_KB_ITEMS`）里取"能匹配上的最长词"，能匹配到就按表相加；一条都没匹配到才退回烹饪方式关键词粗估（基础 380 kcal，命中"炸烤/米饭/肉/青菜"等词加减）。两份理由都会随响应回传，界面照原样显示。
  - **这不是《中国食物成分表》**，只有 68 条，也没有份量概念。菜名里只认出一部分食材时，`source` 会是 `nutrition_kb_partial`，理由里直说"其余字面没认出来，这一餐可能比这个数高"。
  - **打卡链路一次都不会调模型。** 曾有一版把服务器本机 0.5B 模型放进了 `/api/food/log` 的同步路径，实测一次打卡要等 **2.0~2.6 秒**，而且模型给的克数与落库的克数经常互相对不上、成分表没命中时任何 30~3500 的数字都会被当成"AI 精准解析"采纳——已经撤掉，现在实测 0.07~0.24 秒。
- 三大宏量：拿到估算热量后按固定比例倒推——蛋白 25%、碳水 45%、脂肪 30%，再除以 4/4/9 换克数。**同一餐里"白水煮鸡胸"和"红烧排骨"的宏量比例是一模一样的。**
- 训练消耗：客户端写死 220 kcal / 20 分钟提交一条记录；界面计时器按每秒 0.18 kcal 累加，两者不是同一套算法，以入库的 220 为准。
- 剩余预算 = 每日目标热量 − 今日摄入 + 今日消耗。

### 图表（三条，全部由真实流水生成）
- 体重曲线：只画 `weight_logs` 里真实存在的那些日期，一天一个点；完全没有记录时退回档案基线一个点。
- 热量缺口柱（近 7 天）：`净缺口 = TDEE + 当日训练消耗 − 当日摄入`。**这一天一笔未记（包括今天）就是 0，不会拿目标值冒充"已创造赤字"。**
- 宏量配比环：今日没记录时画灰色空环写"今日无记录"；有记录时按真实热量占比分段，某项为 0 就不画那一段。

### 饭点外卖门禁
判据是"今日剩余预算 ≤ 0"。

做到：本 App 入口按钮被拦下 + 震动 + 蜂鸣 + 弹窗建议（温水排钠、豆腐汤）。预算够时把减脂备注写进剪贴板，再跳美团/饿了么；手机没装 App 就打开网页版。

做不到：**它无法锁定手机上别的外卖 App**。所谓"锁定点单通道"只是拦自己页面里那颗按钮。另外两种情况已修：未登录时不再谎报"今日已超标"，而是引导先登录；网络取不到今日额度时既不拦截也不放行，会明说"额度还没取到"。

跳转依赖 `getLaunchIntentForPackage()`，Android 11 起必须在清单里声明包可见性，否则恒返回 null（表现为"跳转"永远只打开网页）。本轮已补 `<queries>`。

### 外卖自律统计（真实事件流）

功勋榜那三颗数字以前是 HTML 里写死的 `5 次 / 3,850 / 1.1 斤`，服务端连一张记录表都没有——任何人打开都显示"5 次"。现在改成真实事件流：

- 新表 `takeout_events`，四种事件：`blocked`（门禁拦下）、`cancelled`（审核后主动退单）、`substitute`（采纳低卡平替）、`launched`（额度充足放行跳转）。
- 少摄入热量只累计 `substitute` 与 `cancelled` 这两种**算得出差额**的事件；`blocked` 上报时带的任何热量都被服务端强制归零，因为系统不知道你本来要点多少。
- 折算脂肪按 `7700 kcal ≈ 1 kg`，界面与回答里都写明这是折算不是实测。
- 没有事件时三颗就是 `0 次 / 0 / 0 斤`，称号显示"尚无记录"，不预先记功。

同类被清掉的写死数据：`本周外卖配额 剩余 1 次`（系统从来没有配额机制，改成"本周真实点单 N 次"）、`自制控油率 92%`（无来源，删）、`连续超标总富余 +580 kcal`（改为按每日超出部分真实累加）、图表的 `起点 70.0kg / 目标 60.0kg / 当前 69.2kg / 目标 450 kcal / 图例 110g·145g·45g`（全部绑真实档案）、`下行稳健`（改为按首末体重算出"已降 X 斤"）、`今日训练已完成！`（那其实是个还没按的打卡按钮，改成"记录今日训练打卡（按 220 kcal 计入）"）。

### 界面显示修复

实拍反馈的三处已修。顶栏窄屏下标题被挤成四行、右上档案胶囊文字竖排溢出：改为顶栏可换行、长文本走省略号。悬浮"下载App"按钮压住卡片文字：App 内直接隐藏这颗按钮（已经装着客户端了，不该再引导下载一次），网页版保留但给主内容留 140px 底部空间。`当前 140 斤 / 目标 undefined 斤`、`离目标体重还有 NaN 斤`：根因是服务端返回下划线字段而前端读驼峰，已在入口处显式映射，并补上"已达标"与"未设目标"两种文案。

### 休息日与运动日（本轮做实）

以前这个切换只改进度环的分母和一句提示，**服务端算额度时永远用同一个目标值，等于选了没区别**。现在：

- `profiles.day_mode` 落库，切换走 `POST /api/profile/mode`，失败会回滚按钮状态并明说没保存。
- 休息日预算 = `rest_cal`，运动日 = `workout_cal`，**真实相差 170 kcal**，剩余预算、门禁锁定、宏量图全部跟着变。
- 训练打卡成功后自动把当天切成运动日，不需要手动改。
- 顶栏下方一行小字直接写明当天预算与差别。

### 每日更新的东西（逐项列清）

| 项目 | 每天怎么变 | 依据 |
| --- | --- | --- |
| 今日剩余预算 | 换日自然重算（按 `log_date` 查当天） | 服务端 |
| 今天练没练 | 以前重开 App 就丢，现在读 `today_workout_done` | 服务端 `workout_logs` |

### 身材记录：两条通道 + 标准拍法

拍照不是必须的。`POST /api/cycle/upgrade`（带照片）与 `POST /api/cycle/measure`（只填体重与腰围）共用同一套 `_progression()` 规则，**没照片照样能建立周期并拿到下一周期安排**；前端按"有没有选照片"自动选端点。

周期页写明了怎样拍才可比：晨起空腹、同一位置同一光线、正面加侧面、卷尺水平绕肚脐不吸腹。报告里只陈述两次实测的差值，并明确标注"依据上面数字的规则判断，非视觉分析"——服务端从不读照片像素。

### 动作标准与视频

32 个动作每个配 3 条标准分解要点 + 1 条常见错误（`EX_STEPS`，按"身形:序号"定位），卡片上"标准动作分解"可展开。

**视频没有内置**：本仓库不含任何教程素材，也没有下载第三方视频的授权。"看演示视频"是按动作名拼一个必应视频搜索链接，交给系统浏览器打开，点之前会提示"视频来自第三方，本软件不内置教程"。倒计时卡片标题写明它对应的是当前身形的哪 4 个动作，结束提示也不再是空泛的"恭喜达成燃脂目标"。

### 顶部排版与电脑/手机版

顶栏改成两行：第一行品牌（标题只留"轻塑"两字，不再被挤成竖排）与账号、视图切换、设置三个图标按钮；第二行是档案摘要条（`165cm · 140斤 · 👑经典倒三角·铠甲腹肌` 从胶囊里挪出来，单独一行、超长走省略号）；再下面是休息日/运动日切换与一行差别说明。

新增"电脑版/手机版"切换按钮（`🖥️`）：电脑版把容器放宽到 1080px 并让卡片走双栏网格，横幅类元素跨满两栏；选择记在 `localStorage`，窄屏首次进入按视口宽度自动选。切换后会重算图表（canvas 宽度跟随容器）。

### 身形目标与动作库
8 款：女 4（S型沙漏、修长轻盈、紧致力量、稳健脱脂）+ 男 4（倒三角、修长衣架子、饱满力量、啤酒肚专项）。每款一张内置 SVG 示意图（画的是理想形体，不是用户本人），驱动两件事：三宏量比例与热量缺口档位（420/500/+250/550 kcal），以及从 32 个动作里选出的那组 4 个。

### 周期身材照
提交体重 + 肚脐腰围（可选照片），服务端插一条 `body_cycles` 并生成一段报告。

- 照片原样存 `/uploads/` 供前后对照，**服务端从不调用任何图像识别，也不看像素**。
- 围度增减只在"上一次和这一次都有测量值"时才计算；注册时不采集腰围，所以第一次提交会写"待补围度"，而不是拿一个编造的基准算出"+7.0 cm"。
- "第 N 周期 (第 x-y 天)"里的天数是 `周期序号 × 7` 推算出来的字符串。**没有任何 7 天间隔校验**，一天提交五次就会得到五个周期。
- 报告说"训练动作进阶、饮食调配更新"只是文案：动作库和食谱不会因提交本表而改写，换方案要去【档案】里选身形。

### 问答顾问（三层，按顺序命中）

1. **先答你自己的真实记录**（`/api/ask`，登录态）。问"我多重""还能吃多少""今天吃了什么""练了没""净缺口""拦截了几次""喝水没""宏量目标""周期腰围"这类问题时，答案直接从你的流水表算出来，不联网、不调模型。以前问"我多重"只会拿到一段通用套话，而体重本来就躺在库里。
2. **答不上再联网**：抓必应国内版的自然搜索结果，返回标题、摘要与来源站点，并在回答开头标明"以下是联网查到的资料（由第三方网站提供，不是本系统的减脂建议）"。实测服务器到 `cn.bing.com`、`baike.baidu.com`、`www.baidu.com` 均 200（0.07~0.16 秒），`api.duckduckgo.com` 与 `zh.wikipedia.org` 不通，所以只走国内可达的那条。第三方标题与摘要在服务端就做了去标签 + HTML 转义，URL 也转义，避免把别人的网页内容当标签执行。
3. **联网失败就明说**：返回"联网查询没成功/没查到可用结果"，前端退回本地规则建议并标注"不含你的真实数据"。**任何一层都不编答案。**

本地规则库（不登录时的兜底）仍是纯关键词匹配，不调任何大模型、不需要 key，界面 5 颗预设问题各有专答。

限频：每用户每分钟 12 次联网查询，避免这个接口变成免费的公开代理。

### 缓存：你打开的到底是不是刚部署的那版

后端在 `/`、`/u/{username}`、`/app.js`、`/style.css`、`/qr.svg`、`/qingsu.apk` 的响应上都加了 `Cache-Control: no-cache, must-revalidate`。在这之前这些响应**一个 `Cache-Control` 都没有**，浏览器按启发式长期缓存，于是出现过这种局面：服务器已经换成新版，老访问者的浏览器还在用缓存里的旧 `app.js`，甚至旧 APK。

首页还在出口前给三处引用挂上版本号（取自盘上文件的 mtime）：`src="app.js?v=…"`、`href="style.css?v=…"`、`href="/qingsu.apk?v=…"`。这样即使某个旧条目已经被缓存在浏览器里，URL 一变它就必须重新取。实测：`touch` 服务器上的 `qingsu.apk`（只动时间戳、内容 md5 仍是 `da0f54c0…`）之后，首页给出的下载链接立刻从 `?v=1792077189` 变成 `?v=1792079653`——**页面上那个下载按钮永远对应盘上当前那份包**。

版本号只在服务端改写，仓库里的 `index.html` 保持裸引用不动。原因是 APK 内的 assets 走 `file://` 加载，没有 HTTP 缓存这回事，所以**这次改动不需要重新打包**。

两个代价写在这，别当成免费的：

1. **全站不返回 304。** Starlette 的 `FileResponse` 只发 `ETag`/`Last-Modified`，并不处理 `If-None-Match`；nginx 那层是纯 `proxy_pass`，没开 `proxy_cache`。实测带 `If-None-Match` 请求 `/app.js` 与 `/qingsu.apk` 都照旧返回 200 全量。所以 `no-cache` 的落地成本是每次访问重传首页 69.5 KB + `app.js` 97.4 KB + `style.css` 38 KB ≈ 205 KB。要省掉它得自己实现条件请求（约二十行），本轮没做。
2. **改了 `app.js` 必须重新打 APK 才影响 App 用户。** 手机 App 的前端打包在安装包里，服务器再怎么更新都到不了已装的 App。这条是这轮审计里"多端同步"最容易踩的暗坑：网页版和 APK 版是两个独立分发渠道，只有当 `qingsu.apk` 内 `assets/app.js` 的 md5 与仓库一致时，两边才算同一版。
