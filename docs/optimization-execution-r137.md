# r137 执行记录：3D 演示改成蓝色线框全息风

日期：2026-10-17。版本：versionCode 20 / 1.8.2。承接 r136。

## 1. 触发点

机主丢来一张参考图（一个蓝色线框全息女性人体，A 字站姿，网格均匀）：
"你做的运动动画还是好丑，你可以用这种线条 3d 人物做动画，这个好看些"。

这条反馈值得记下来的地方：r135/r136 我一直在**几何和配色**上使劲（肌肉鼓起、
衣服、头发），而他要的是**渲染风格**的换法。线框风格对我这套程序化体块几乎是白捡的——
旋转体天生的三角网格就是他要的那种网格，不需要任何资产授权。

## 2. 改了什么（全在 `body3d.js` 的渲染层，骨骼与姿态解算一行没动）

- **每个体块两层**：里面一层半透明暗芯（`0x0D2B47`，不透明度 0.72），
  外面一层亮线框（`0x5BD8FF`）。暗芯的作用不是好看，是挡住"身体另一侧的线穿过来"
  ——纯线框在躯干这种重叠多的地方会糊成一团网。
- 暗芯开 `polygonOffset`，否则它和**自己**的线框在同一深度抢，线会断。
- **发力部位换线框颜色**（琥珀 `0xFFB454`）而不是换实心：线框风格里换色比涂面读得清楚。
- **轮廓按弧长重采样到 16 圈**（`resample()`）。原来每条轮廓只有 4~6 个控制点，
  直接旋出来躯干就是几张大格子，看着空；参考图的"密"靠的是纵向圈数，不是新形状。
  重采样后三角形数 6132 → 14404，单帧仍是 2ms。
- **三盏灯整套删掉**：线框和暗芯都是 `MeshBasicMaterial`，不吃光照。
  r135 为皮肤调的暖主光/冷补光/轮廓光当场作废——这也说明上一版在光照上花的功夫
  对这个风格是零价值的。
- 体块表里的 `c:`（衣服/皮肤分类）**保留**，切回实体渲染只改 `buildRig` 一处。
- 地垫配色跟着换成冷蓝发光椭圆，和线框同一套语言。

## 3. 判据

`selfTest` 的口径本来就是从**像素**量的，所以换风格不需要改判据，反而正好验证了
"判据量的是结果而不是实现"：

- 真机（MuMu `127.0.0.1:16384`，正式包 versionCode 20）：`DeviceSmokeTest#releaseUserJourney`
  `OK (1 test)` 32.5 秒；五档宽度 320/360/390/768/1440 每档硬校验、断点 `[340,380,900]` 全覆盖；
  4 个动作逐个 `selfTest`：`coverage` 9.4~15.8、`fill` 79.8~81.5、`ndcMax` 0.814~0.900、
  `orphan` 全 0、`nanBones=0`、`badFrame=null`、41 次 draw call、单帧 2ms。
- 本地三套：后端 290 全绿、前端 225 全绿、集成 25 组通过。
- **`coverage` 阈值差点变成假红**：线框很细，如果只画线不画暗芯，墨迹占比会掉到
  判据下限（3%）以下——那时"渲染是对的"和"判据红了"会同时发生。
  现在暗芯把轮廓填住，`coverage` 量的仍是人体剪影，阈值不用动。
  这条留着提醒：**判据的口径要跟着渲染方式一起复核，不能默认它一直成立。**
