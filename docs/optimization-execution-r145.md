# r145 执行记录：3D 全息人体下线，换成火柴人，画布上的浮层全部搬走

日期：2026-10-18。版本：versionCode 28 / 1.9.6。承接 r144。

## 1. 机主这句话指向两件事

「这个 3D 动画不要了，又丑又不标准，或者你给我换成火柴人都比这好看些。手机看网页还有各种遮挡动画，真难看。」

拆开是两条独立的账：

- **不标准**：关键帧表（`exercise_poses.json`，32 动作 × 4 帧）给的就是 16 个 **2D** 关节点。
  上一版把它们当 3D 骨架用，左右肢体的"深度差 0.06"是我赋的常数、不是解出来的，
  再叠一次透视投影——屏幕上那团体积是凭空造出来的，怎么调都不会标准。
- **遮挡**：视口里挂着三处 `position:absolute` 浮层（视角提示、相位徽标、说明），
  下面还有一排四颗视角按钮。手机上浮层正好压在人形上。

## 2. 做了什么

**渲染层整条换掉**（`app.js`，删 589 行、加 254 行）

- 删 `body3d.js`、`vendor/three.module.js`、`vendor/GLTFLoader.js`、
  `vendor/BufferGeometryUtils.js`、`models/cesium_man.glb`、`models/CREDITS.md`，
  合计 **1,953,253 字节**；`index.html` 不再挂 `type="module"`，页面也不再需要 WebGL。
- 服务端撤掉 `/vendor/{name}`、`/models/{name}` 两条静态子目录路由与 `_STATIC_SUBDIRS`
  白名单（没有子目录要发了），`PUBLIC_ASSETS` 去掉 `body3d.js`。
  `scripts/package-release.py` 不再收 vendor/models；`deploy.py` 的 `copytree` 保留——
  那是"目录树要整层搬"的通用正确性，不是为 3D 留的。
- 火柴人：`STICK_SEGMENTS` 13 根线段（头-颈-胸骨-骨盆一条中轴 + 肩线 + 髋线 + 四肢），
  层序固定 **远侧 → 躯干 → 近侧**；浅底渐变 + 一条地面线；矢状面动作里背向镜头那一侧
  画细画淡，正视动作左右等权；发力那根换绿并叠一圈半透明粗线做脉冲，
  **不用 canvas `shadowBlur`**（2 倍 dpr 上会糊成一团绿，正是上次"丑"的来源之一）。
- 取景按**这组动作全部关键帧的关节并集**算，四边留出头半径，所以既不裁头也不随
  动作呼吸式忽大忽小。头的大小从恒定骨长（胸骨→骨盆）按比例推，不取肩宽——
  矢状面里左右肩几乎重合，按肩宽推会画出一个没有头的人。

**遮挡清干净**（`index.html` / `style.css`）

- 三处 absolute 浮层、四颗视角按钮、第二张 WebGL 画布全部删除；
  相位与说明改写成画布下方的 `.exd-strip`（正常流），控制栏 `.exd-ctl` 在其下。
- 拖拽旋转的 `touchstart/touchmove` + `preventDefault` 一并删掉：
  以前手指在画面上一拖，整页就滚不动了。

**真机量出来两层"糊"**

- 第一层：画布位图尺寸量在弹窗 `show` **之前**，而 `.modal-overlay` 未打开时是
  `display:none`，`getBoundingClientRect()` 全是 0 → 那段 dpr 校正从没有生效过，
  手机一直拿 340×360 的位图拉伸。
- 第二层（改成 show 之后量才暴露）：卡片带 `slideUp` 动画，起手 `scale(0.97)`，
  `getBoundingClientRect()` 把这个瞬时缩放也算进去了，位图又小一圈。
  MuMu 320 档实测 `W=357`，而 `245×1.5` 应为 368。
- 现在量 `clientWidth`（不吃 transform）。修完实测：**320 档 `W=368 = 245×1.5`、
  360 档 `W=428 = 285×1.5`、全宽档 `W=686 = 457×1.5`**。

**320 档控制栏那句说明被挤成竖排**（截图里一眼看见）

`.exd-note` 原来只写 `flex:1`，两颗按钮一挤只剩四个字宽，一句话排了十几行。
改成 `flex:1 1 200px` + `min-width:0`，容器 `flex-wrap:wrap`，放不下就整句落到按钮下面。

## 3. 判据与标定

判据 **后端 395 + 前端 243 + 集成 27 + AI 契约 6**，全绿。

只服务于 3D 的那批判据整段删除：体块解剖朝向（脚宽>厚、躯干压扁、巴掌不是圆球、头颅竖直轴最长、肘膝关节帽）、vendor 三件入库、glb 与授权说明入库、ES 模块加载、发布归档含子目录、双渲染模式文案、零驱动退回、绑定姿态自检、视角工具栏与叠层那五条。`WebGLProbeTest` 整个文件删掉——**不能再留一条会在 3D 已经不之后仍然宣称「3D 已验证」的判据**。上面那两组数字是删完再加完之后的净总量，不是新增条数。

新增的都是真跑出来的，不是看源码里有没有某个字符串：

| 判据 | 量法 |
| --- | --- |
| 32 动作 × 3 屏宽 × 10 相位没有被裁 | 记录 `drawFrame` 每一次 `moveTo/lineTo/arc/fillRect` 的坐标，任一落笔点出界即红 |
| 人形没缩成一小条 | 同一批坐标去掉地面线与背景，占宽或占高必须 > 45% |
| 取景框恰好等于关节并集 | 真调 `stickBox()` 与逐帧重算的并集逐边比对；只要求"包住"的话，把框写成整张画布也能绿 |
| 发力标签真的点亮 | 12 个原型各画一帧，断言绿色真出现在 stroke/fill 颜色里 |
| 远近侧只在矢状面出现 | 冠状面动作里出现淡色 `#A9B7C6` 即红 |
| 画布上没有叠层 | 结构判据（舞台里只有一张 canvas）+ 真机 `elementFromPoint` 逐点 |
| 位图量在 show 之后 | 源码顺序判据，反样本是"把 show 那行删掉" |

**变异标定共跑 13 项，其中 2 项一开始没生效，都记下来：**

1. 「正视也分远近」——判据在**后端**套件里，我却拿前端套件去验，自然不红。指对套件后红。
2. 「取景框取全部关键帧的并集」原来是两条 `"e.frames[i].pose" in js_txt` 之类的**字符串判据**，
   把分支短路成 `if (false)` 照样绿。换成真跑 `stickBox()` 的行为判据后才红。
   顺带发现"只要求包住"太松：把框写成整张画布仍然绿，于是补了占幅判据 + 框必须**恰等于**并集。
3. 新写的并集判据自己带了个 bug：比较对象误写成**累加中的** `u` 而不是返回的 `b`，
   导致正确实现上恒红（第一条关节必然 `< Infinity`）。修完先跑正样本再跑反样本。

  上的实际观感仍未人工看过**，不写成已通过。
