# r140 执行记录：三块界面重做 + 下载按钮在 App 里其实下不了包

日期：2026-10-17。版本：versionCode 23 / 1.9.1。承接 r139。

## 1. 机主问的两件事

**「这里下载会不会实时更新成服务器那个 apk」**——量完的回答是：会，但他看到的那句说明是假的。

- 现役包：`/version.json` 报 `size 5941497 / sha256 e49dcbd0…`，真下载一次拿到的字节 SHA-256 与它一致；首页那颗按钮的 href 是 `/qingsu.apk?v=e49dcbd0e263`（服务器出口按包指纹挂版本号），包本身 `cache-control: no-cache, must-revalidate` + ETag。三处都对得上，**下载到的一定是现役包**。
- 但按钮上那句「实测下行约 0.3 MB/s，这个包大约要 18 秒」是**别人机器上量过一次就再也不变的写死数**，对 5G 上的手机完全不准。改成用一次 256KB 分段请求（服务器实测支持 `206 + accept-ranges`）量这个人当前这条链路；测不出来就显示「下载速度未测」，不回落成好看的数。
- 顺手把「我下的到底是不是新包」变成屏幕上看得见的一行：`这个包 build 23（指纹 ad4900a6）· 手机上 build 23 · 与手机一致`。只写「你已经是最新」在手机比服务器新时就是假话，所以两边号都要写出来并说明关系。

**「这三个界面丑得离谱」**——根因不是配色：`features.css` 只有 21 行，每个动作都是同一颗绿色描边胶囊，五颗排下去既没有分组也没有主次，读起来像调试页。

## 2. 改成了成熟那套形状

- **分组列表**：行 = 标题 + 说明 + 右侧控件，发丝线分隔，外层圆角卡片，配小标题（总开关 / 大屏显示什么 / 有效期）。
- **真开关**：`appearance:none` 的 checkbox，键盘与读屏照旧可用，选中态有独立样式。
- **分段控件**：历史记录四类切换用 `aria-selected` 表达当前项，不再画五颗一样的胶囊。
- **主次按钮**：保存=实心渐变，更新密钥/通知权限=描边，删除=红底；原来三颗完全同权重。
- **记录条目**：日期 · 名称一行，热量做成 chip，来源过一层映射表变成人话——屏上原来直接印 `nutrition_kb_partial`、`legacy_estimate` 这种内部枚举，等于把调试字段交给用户。
- 设置卡的五个动作从「胶囊汤」变成带图标、说明行与箭头的列表行，草稿数变成行尾徽标。
