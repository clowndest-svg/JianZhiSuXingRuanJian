## 1. 机主的两条不满

**「这回答的什么玩意，能不能和豆包一样可以联网随便聊天」**——截图里他问「你好」，
系统回的是：

> 【没查到】 这个问题里我没有能确认的减脂相关词，联网搜回来的东西判断不了对不对题，
> 所以不拿它凑答案。换个带具体食物或场景的说法再问……

根因很清楚：问答只有「本人流水 / 内置场景 / 联网检索」三条路，**没有一条是给"人话"准备的**。
一句寒暄走到检索口径下，因为认不出减脂领域词，被当场拒了。这不是措辞问题，是少一层。

**「这个弹窗前端设计和排版太丑了，和软件一点也不对应……像在敷衍我」**——
`核对餐食与份量` 是上一轮排版重做时**漏掉的一个 `toolDialog` 调用点**：
它的模板还是裸 `<p>` / 裸 `<label>` / 裸 `<button>`，所以渲染出来就是浏览器默认样子，
和同一套弹窗里已经改成分组列表的那几个完全不是一套东西。

## 2. 问答顺序改成：流水 → 场景 → **闲聊** → 联网

- **确定文案优先**：打招呼、道谢、告辞、「你是谁」、「你能做什么」、「减肥好累」、「无聊」
  这几类走写死的回答。理由很实际——服务器上那个模型只有 0.5B，
  让它自由发挥聊天它会顺嘴编一个体重或热量出来，那比不回更坏。
- **接不上才让模型开口**，而且输出要过硬校验：出现任何数字（斤/kcal/千卡/大卡/岁/天）就丢掉、
  出现「作为一个 / 抱歉我无法 / 一定能 / 保证 / 治愈 / 停药」这类话也丢掉、超过 160 字丢掉；
  模型没跑或输出越界时不装作成功，退回到一句诚实的接话提示。
- **联网口径放开**：不再只认那 90 个减脂词，改成按问题里的**实词**去搜
  （把「是什么/怎么/为什么/能不能」这类疑问词切掉后剩下的片段）。
  相关性闸门一条没松：搜回来不含这个实词的、纯字词页，照样不用。
- **两条配额分开**：减脂题走原限额，开放题每人每分钟 6 次。
  这一步是必须的——「认不出领域词就干脆不联网」当年就是为了防止有人连问
  「量子计算是什么」把真正要查的减脂问题挤到限流后面。放开联网不能把这个保护丢掉，
  所以换成更细的口径，而不是删掉判据让它变绿。
- 界面给这条来源加了标签 **【闲聊】**，和【你的真实记录】/【联网资料】并列。

## 3. 判据

判据规模 **后端 363 + 前端 237 + 集成 27 + AI 契约 6**，全绿。

- 新增闲聊判据 26 条：九句寒暄必须 `source=chat` 且回答里**一个阿拉伯数字都不许有**；
  「我今天吃了多少」仍走流水、「中午吃多了怎么办」这类正事即使前面加了「你好，」
  也不许被当成寒暄敷衍；实词提取的正反样本（`量子计算是什么 → ["量子计算"]`、
  不把「什么」当主题词）；闲聊关键词不许用单字；开放题小配额用完后要说限流而不是装没查到；
  开放题限流不许影响减脂题。
- **三条守旧规则的判据被这次改动撞红，我没有删它们**，逐条换成新契约：
  「认不出领域词就根本不联网」→ 改成「没有领域词也会按实词试联网一次」
  +「试联网仍不许拿不相干结果凑答案」；「拒答不耗尽联网配额」→ 改成
  「开放闲聊不吃减脂题的配额（两条配额分开）」；「不联网时如实说为什么不答」→ 拆成
  「点名要的是什么词」+「邮箱页与字典页没进答案」。旧契约的**目的**保留，换掉的只是手段。
- 弹窗排版补了 5 条静态判据，专门堵「下一个新弹窗又用裸标签」：
  每个 `toolDialog` 模板正文**一开头**必须是结构件、模板里每个按钮都必须带样式类、
  输入框必须挂在表单行/记录行上。变异标定两次：
  ① 把餐食弹窗退回裸按钮 → 红 2 条；② 只删掉草稿模板开头的 `class="td-lead"` →
  第一次**没红**（我那条判据只查"模板里出现过 td- 类"，太松），补了"查正文开头 60 字符"之后红 2 条。
  另外那条判据一开始把 `toolDialog` 自己的函数体也当成弹窗数进来了（误报），
  改成只数调用点。
- 真机新增 4 条：餐食核对弹窗的输入框必须挂在表单行上且高度≥40px、
  两个按钮背景必须不同（主次）、餐食原文必须是粗体主角；
  闲聊回答必须带【闲聊】标签且那段文字里没有编造的数字。
  `toolDialogsAreReadableOnDevice` 与 `releaseUserJourney` 均 `OK (1 test)`。
