# 轻塑 APK / 网页审查与优化执行方案

审查日期：2026-10-16（Asia/Taipei）。源码基线：`6b33bd2`；审查开始时工作区干净。当前 APK：`com.fitcoach.shapemaster`，versionCode 10 / versionName 1.3.1，5,703,758 字节。

本次交付是审查结果和执行方案，未修改业务代码、未发布版本、未向生产写入测试数据。本文的工期和性能指标是规划值，不是已经达成的结果。

## 1. 结论与推荐路线

项目已经具备账号、饮食/体重/饮水/训练记录、图表、公开监督页、AI 问答、动作演示和 APK 更新入口，适合继续迭代。但目前最需要的是修复核心流程和数据可信度，而不是继续堆叠功能。

建议保留 **Android 原生壳 + 共用 H5 + FastAPI 单体**，先完成安全与正确性整改。当前没有证据支持立即重写成 Flutter/React Native、拆微服务、引入消息队列或更大的模型。SQLite 是否升级，应由实际并发和写入压力决定。

推荐顺序：**安全与隐私 → 分享/登录/记录闭环 → 每日数据与统计口径 → APK/网页体验 → AI 质量与性能 → 发布验收**。

四项应作为扩大使用范围前的阻断项：

1. 明文 HTTP 同时承载登录、健康数据和安装包更新。
2. 上传目录无需鉴权，且允许 HTML 等非图片内容。
3. 个人模型回答进入全局知识库，被其他账号读取和复用。
4. 当前分发 APK 使用 Android Debug 签名且 `debuggable=true`。

## 3. P0：先解决安全与隐私边界

P0 表示发布阻断或可能造成跨用户数据暴露；不是所有问题都已经发生过实际泄漏。

### SEC-01：把 HTTPS 和环境配置作为一项完整改造

**证据**：`server.py:30`、`app.js:6`、`UpdateManager.java:29` 等硬编码 HTTP 地址；Manifest 允许明文。公网本轮 GET 仍停留在 HTTP 200，没有重定向。前端仅对指定 IP/localhost 使用同源，模拟 `https://example.test` 时仍请求 `http://124.220.54.64`。

**影响**：登录密码、令牌、身体记录和更新元数据缺少传输保护；只给网站加 HTTPS 而不改 APK/API 地址，会留下旧链路或触发混合内容问题。

**执行**：

- 确定稳定的 HTTPS 入口和证书自动续期；网页 API 优先同源相对路径。
- 后端 `SITE_BASE`、数据库/上传目录、模型与 Redis 地址改为环境配置；APK 地址由 build variant/BuildConfig 提供。
- 生产关闭宽泛明文访问；如保留设备本地模型，单独验证回环地址的网络策略，不给整个应用放开 HTTP。
- 明确 CORS 允许来源，分离网页、APK 资源域名和开发环境。私密 API、分享页使用适当的 `Cache-Control: private/no-store`。
- 增加 `nosniff`、Referrer-Policy、框架嵌入限制；CSP 先 report-only，清理内联事件后逐步收紧。
- HTTPS 稳定后再启用 HSTS；旧 APK 的过渡期与最低兼容版本需同步安排。

**验收**：网页、APK 登录与读写、公开页、照片和更新都经 HTTPS；全链路不回落生产 HTTP；证书续期与旧客户端升级路径分别验证。

### SEC-02：身材照片改为私有媒体资源

**证据**：[静态目录挂载](D:/RuanJian/JiaZhiSuXianApk/server.py:166)、[上传处理](D:/RuanJian/JiaZhiSuXianApk/server.py:1263)。本地以 `photo` 上传无脚本的 HTML 标记文件返回 200，未登录 GET 该文件返回 200、`Content-Type: text/html`。文件名含用户 ID、周期号和秒级时间；应用层没有大小、真实图片格式和像素上限检查。

**影响**：身体照片访问控制独立于公开页密钥；上传的主动内容可被同源提供，存在同源脚本注入风险。本轮没有执行恶意脚本，也没有访问任何生产用户照片。实际网关上传上限未核验，不能把应用层缺限额等同于线上无限上传。

**执行**：

- 移除直接暴露上传目录的方式，使用 `media_id`、所有者、授权范围和鉴权下载接口。
- 默认只本人可见；公开分享照片必须是独立可选权限，使用短时授权 URL，分享撤销后不可继续访问。
- 校验真实文件类型、解码图片、限制大小/尺寸/数量；拒绝 HTML/SVG 等主动内容，统一重编码，去除 EXIF 位置信息。
- 使用随机对象名和独立媒体域名/响应策略；分块读取，避免 `await photo.read()` 一次读完整文件。
- 补文件/数据库失败回滚、孤儿文件巡检、保留期限和删除策略。

**验收**：匿名或其他账号访问私人媒体得到 403/404；HTML、伪装图片、超限文件被拒；正常上传/预览/删除和明确授权分享可用。

### SEC-03：停止把个人 AI 回答写进全局知识库

**证据**：[上下文读取](D:/RuanJian/JiaZhiSuXianApk/server.py:1782)、[客户端回写](D:/RuanJian/JiaZhiSuXianApk/app/src/main/assets/app.js:3847)、[全局写入](D:/RuanJian/JiaZhiSuXianApk/server.py:2020)。`kb_entries` 只有问题键，没有 `user_id`；`how` 未入库。账号 A 回写的测试标记能出现在账号 B 的 `/api/ai/context`，并在 B 提问时以 `source=kb` 返回。

**影响**：个人回答可能携带身体数据/忌口等信息；任意注册账号也能覆盖共同问题的答案。HTML 转义只解决显示安全，不能解决内容污染和隐私隔离。

**执行**：

- 立即禁止客户端答案直接进入共享可信知识库；临时可关闭该回写能力。
- 分成用户私有回答缓存、用户记忆、经过审核的公共知识三类。
- 私有缓存强制绑定 `user_id`；公共知识仅由受信采集流程写入，保存来源、审核状态、版本、时间和内容摘要。
- 旧全局条目先备份并隔离为“来源不明”，审查后迁移；不能直接假定旧条目均可共享。
- 当前“黑咖啡有什么优点/有什么风险”生成相同键，缓存键须包含规范化完整问题、意图、知识版本及必要的用户上下文版本。

**验收**：A 写入的私有标记不能被 B 的任何接口取得；普通账号不能修改公共知识；相反意图的问题不复用同一答案；旧数据迁移前后都有可追踪清单。

### SEC-04：建立可升级的正式 APK 发布链

**证据**：[Gradle](D:/RuanJian/JiaZhiSuXianApk/app/build.gradle:23) 的 release 使用 debug signing；当前 `qingsu.apk` 实测证书为 `CN=Android Debug`，清单 `debuggable=true`；更新清单和下载走 HTTP，客户端仅判断版本号，没有使用清单哈希校验下载。

**执行**：

- 先核验现有签名私钥、已安装用户版本和证书兼容策略，再设计正式签名迁移；不能直接换证书后宣称原地升级完成。
- 固定 release 构建任务和私钥保管方式；私钥不入库，备份与访问权限可审计。
- 发布门禁解析实际 APK，断言 `debuggable=false`、包名/版本/证书正确、资产哈希匹配。
- HTTPS 版本清单提供 SHA-256、最低支持版本、兼容说明和简短更新日志；限制更新 URL 的协议/主机。
- 若下载仍交给外部浏览器，要如实说明客户端没有做包体哈希校验；若实现应用内下载，则完整验证哈希和预期签名后再交系统安装。
- APK、网页资产、后端 API 兼容版本必须纳入同一发布清单。

**验收**：全新安装和旧版升级两条路径分别通过；升级后账号/数据仍可访问；拒绝错误签名、损坏包及不允许的下载地址；退出 Activity 后更新回调不弹失效窗口。

## 5. APK 与网页各自应怎样优化

### 5.1 APK：围绕快速记录和可靠设备能力

保留同源业务逻辑，原生层集中负责系统能力。

1. **WebView 收口**：当前 `file:///android_asset/`、`setAllowFileAccess(true)`、全局 `AndroidBridge`、默认 `WebViewClient`。评估迁到 WebViewAssetLoader；明确受信页面域、禁止不受信顶层跳转、外链交外部浏览器；原生桥按来源/参数约束，限制可启动包名和 URL 协议。
2. **权限按功能请求**：在用户开启提醒或查看外卖使用统计时说明用途、请求权限，避免首开多个弹窗；用户拒绝后保留可用路径。现在授权提示暗示“到点提醒”，但没有后台调度，应先修正文案。
3. **提醒先定义可靠性**：普通提醒用适当的系统调度机制；明确允许的时间偏差、时区变化、重启、Doze 和厂商省电行为。通知授权不等于已经拥有后台任务。
4. **返回与生命周期**：返回键先关闭弹窗/动作演示，再导航，再退出；处理计时器、音频、动画和未完成文件选择回调；更新回调检查 Activity 生命周期。
5. **拍照与导出完整链路**：当前仅使用系统文件选择 Intent。验证“选照片”和“拍新照片”能否兑现界面承诺；如需相机，补相机 URI/FileProvider 及取消处理。CSV 下载在 WebView 内不能只假设 `blob:` + `<a download>` 成功，应提供可验证的原生保存/分享路径。
6. **轻量离线能力**：先缓存最后一次已同步数据并标日期；草稿离线可编辑；联网后带幂等键补交；账号隔离和退出清理必须同步实现。不要先把未知状态画成0。
7. **本地模型入口降级为高级设置**：当前 APK 没有随包模型，127.0.0.1 健康检查不等于有可用聊天模型。默认给普通用户稳定服务器路径；接入本地引擎时同时检查协议、模型、CORS/网络和实际回答能力。

APK 验收矩阵至少覆盖 minSdk24 的最低支持路径、Android 10/12、13+通知权限、目标升级系统，以及一台有厂商省电管理的真实设备；覆盖全新安装、原地升级、离线启动、锁屏、旋转、键盘、权限拒绝/恢复。系统版本升级前核对目标分发渠道的最新要求，本轮不假定 targetSdk34 足够。

### 5.2 网页：本人工作台与访客监督页分开

1. **本人工作台**：突出今日待记录、快捷记餐/称重/喝水、同步状态；图表、流水筛选和周报为桌面强化功能。
2. **访客监督页**：显示被分享的进度、更新时间、有限统计和打气；避免让访客面对无法提交的本人表单。
3. **移动导航减负**：当前7个主入口挤在手机底部。建议验证“今日、记录、训练、趋势、我的”5类归并，AI从相关任务进入或作为固定轻入口；先做点击路径和低保真原型，再定最终导航。
4. **可访问性**：移除 `user-scalable=no`；主操作可键盘访问，div点击控件改语义按钮；label关联输入；弹窗焦点约束/返回/ESC；图表提供文字摘要；颜色不作为唯一状态提示；支持减少动画。正文优先14–16px，常用触控热区以44–48px作为设计目标。
5. **统一状态**：加载、空数据、离线、服务错误、权限未给、登录失效各有不同视图；使用组件内重试，不用一串toast代替当前状态。
6. **弱网与性能**：主页面、动作3D、AI、报表按模块分离，非首屏功能按需加载；公开轮询可见时才运行；静态资产内容哈希并配置压缩/长期缓存，HTML短缓存。4个核心文本文件目前约482KB原始大小，应先量压缩与解析成本。
7. **PWA 放后面**：HTTPS和离线/同步语义稳定后再考虑安装、离线外壳；Web Push另做能力检测，不应当作所有浏览器必有功能。

以上视觉和交互调整为设计建议。本轮没有真实浏览器尺寸测量，因此不把“已无溢出/遮挡”写成结论。验收至少覆盖320/360/390/768/1440宽度、200%缩放、中文长用户名、长聊天、键盘弹起、空数据和失败状态。

## 6. AI：质量应由语义与事实决定

### AI-01：统一路由和来源，不让本地模型绕过规则

当前 `askAnyEngine` 在本地可用时直接生成；服务端的本人数据路由、场景规则和记忆指令并未先执行。这意味着“我多重”“记住……”等问题在不同引擎下可能有不同语义。

执行：将数据查询、记忆写入、权限、场景选择做成统一决策层；模型只组织允许的内容。本人数字通过结构化字段输出并带字段来源，不能靠提示词保证不编。默认不传无关的“全局最近6条知识”；外部模型只获得当前问题需要的最少上下文。

验收：server/local/auto三种模式对同一事实、记忆指令、拒答边界结果一致；本地故障切换说清来源；本地-only失败不被标成“两个引擎都失败”。

### AI-02：重新定义评测成功

**证据**：`_ai_eval.py:145` 主要检查答案数字是否出现在整个payload数值集合；同一个数属于体重还是热量不被区分。web类允许 `none`，scene类主要判source，且脚本结尾无论失败多少都返回0。

执行：

- 固定训练/调规则题与独立验收题，增加同义、否定、相反意图、多轮、单位、时间范围、少量信息、特殊人群和提示注入样本。
- 把正确率、合理拒答率、无依据断言率、来源有效率、个人数据引用准确率分开，不把“全拒答”当优秀。
- 答案核验采用“数值+单位+字段+用户+日期”的绑定，而非全局数字集合。
- 评测失败必须非零退出；产物保存问题、路由、答案、来源、耗时、失败原因和运行版本。
- 加双端决策与跨用户隔离评测，保留人工抽检和领域内容复核。

“104题100%”只能描述既有题集和断言结果，不能等同总体回答准确率。模型升级放在完成上述评测之后，按增益、延迟、内存与费用决定。

## 9. 建议的模型与接口契约

渐进增加以下概念，不要求一次性替换全部数据库：

| 数据模型 | 关键字段/约束 | 解决的问题 |
| --- | --- | --- |
| sessions | user_id、token_hash、device_id、created_at、expires_at、revoked_at | 多设备、过期、退出撤销 |
| daily_state | user_id+local_date唯一、timezone、day_mode、budget_snapshot、algorithm_version | 跨日模式和历史口径 |
| records | client_request_id唯一、occurred_at、local_date、source、revision、deleted_at | 幂等、补录、修改与审计 |
| nutrition_details | portion、unit、ingredients、source、confidence/unknown、estimator_version | 可解释的营养估算 |
| media | media_id、owner_id、mime、bytes、storage_key、visibility | 图片鉴权和生命周期 |
| share_grants | owner_id、key_hash、scope、expires_at、revoked_at | 可撤销的最小范围分享 |
| private_ai_cache / public_kb | 前者user_id隔离；后者来源/审核状态/版本 | 隐私、缓存污染与来源追踪 |

接口原则：本人数据与公开数据使用不同schema；写入响应返回 `record_id/revision/saved_at`；同步返回 `as_of/local_date/status`；估算值携带来源与单位；错误包含稳定code和可理解message；前端不自行拼分享URL，也不再从CSV反推业务数据。

历史迁移采用新增字段/新表、回填、兼容读写、核对、再切换的方式。不能把缺失历史预算、来源或用户确认状态补成“已知事实”；没有依据的字段保留unknown。

## 10. 验收与发布清单

### 10.1 自动化必须新增的场景

- 双用户双设备会话；退出撤销；A数据不得出现在B的缓存、AI、媒体、导出或公开页。
- 注册→初始化→第一笔记录→同日修正→跨午夜→第二天→周报，全链路对账。
- 多次点击、相同幂等请求、响应丢失后重试、网络先断后恢复，只出现预期记录数。
- 无记录、部分记录、完整记录且零缺口、只有称重/饮水，分别有正确语义。
- 合法/非法文件、匿名下载、分享撤销、超限上传、图片解析失败，数据与文件状态一致。
- 四错一次成功后计数重置；Redis不可用时限流与故障信息可信。
- 不同问题意图不能碰同一缓存；本地与服务器路由一致；评测失败进程非零退出。
- 真实FastAPI客户端验证参数校验、依赖鉴权、multipart、响应schema；真实浏览器验证DOM/布局/交互。stub保留作快速回归。
- 负向检查采用明确mutation或固定基线，替换目前提交后等于当前代码的 `--mutant=HEAD`。

### 10.2 人工/真实设备验收

- APK安装与升级、签名兼容、通知拒绝/重新授权、使用情况权限、文件选择取消/照片上传、系统保存/分享、锁屏计时、返回弹窗。
- 网页手机/桌面、至少两种浏览器内核、长用户名/长回答、200%缩放、键盘导航、离线/超时、分享访客和本人之间切换。
- 健康相关规则和文案由具备相应知识的审核者复核；减少“偷懒”“严格限制”“真实燃脂”等不准确或指责性描述。
- 整个验收只使用指定测试数据；不在生产进行恶意上传、批量注册或故障注入。

### 10.3 发布与回滚

1. 固定候选commit，生成依赖/迁移/文件哈希清单，备份数据库和媒体；确认恢复可读。
2. 在隔离环境执行新增用例、现有432条回归和真机升级；记录未通过项，不以“已打包”替代通过。
3. 服务端先发布兼容旧客户端的版本，验证API；再灰度网页与APK。
4. 通过只读健康检查和测试账号走注册/登录/打卡/分享/导出/AI，核对页面资产、APK和版本清单。
5. 若出现5xx、数据不一致、跨账号可见、安装升级失败，停止扩大灰度，按迁移类型执行回滚或向前修复。
6. 代码回滚只适用于兼容schema；数据库恢复必须先保存切换后增量并评估影响，不能直接覆盖导致新记录丢失。Android也不能假设安装低versionCode即能回滚；预留更高版本号修复包。

扩大使用范围的门禁：无未解决P0；核心P1完成；APK与网页真实流程有证据；备份恢复成功；实际支持范围和未完成能力在文档/产品中一致。
