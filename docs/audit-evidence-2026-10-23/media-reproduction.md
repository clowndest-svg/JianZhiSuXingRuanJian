# A14 中途隔离复现步骤

受测主仓快照：`838a284adadcfd8d2a9892f37c2009154ad6942d`；后台本地快照：`2c33a45`。该记录描述施工中的行为，最终交付后应重新测试。本次未修改业务或测试代码。

本次探针复用后台 `tests/test_ops_api.py` 的 `OpsApi.setUp/tearDown` 创建临时目录、独立数据库、密钥和两个合成账号，Redis 调用按既有夹具隔离。仅对本地 TestClient 发送请求，未访问生产账号或媒体。临时探针保存在被忽略的本地审查目录，没有作为产品代码交付。

1. 生成一张 600×600 的纯色 JPEG，发送到本地 `/api/community/media`，得到文件名与归属登记。
2. 在临时库里建立两个合成账号的双向关注，满足私信图片的业务前置。
3. 通过产品 `_deliver` 发送 kind=image 的私信，保存消息返回的签名 media_url。该函数与 HTTP/WS 共用落库路径；不是凭空签一个无业务引用的文件。
4. 不带业务登录头访问保存的 URL，记录 200 和原始字节摘要。
5. 以发送者身份调用 `/api/chat/recall`，传入 message_id，确认 200。
6. 使用保存的旧 URL 再次发起一个全新读取请求。观察到 200、字节摘要相同、Cache-Control 为 private,no-store。
7. 给同一 URL 增加 thumb=1，观察到 200、private,max-age=300。这是私信图片，不因参数就应被当作社区缓存素材。
8. 保留真实签名内容，仅替换受测模块看到的时钟，使其为 expires−1 秒；再次请求缩略图，仍返回 max-age=300。该步骤检验 TTL 算法，不是浏览器缓存实测。
9. finally 中执行夹具 tearDown，删除整份临时库/账号/媒体/密钥。

原始观测值见 [media-probe.json](media-probe.json)。正式验收应先对最终候选复现，再覆盖所有真实媒体类别、授权撤销、参数变体、HEAD/Range 和浏览器缓存；本轮没有将服务端响应头观测替代浏览器证明。
