## 2. 本轮落实

**弹窗与键盘**：五个弹窗声明为 `role="dialog" aria-modal="true"` 并给可读名字；打开时焦点进弹窗、Tab 在弹窗内循环、背景整体 `aria-hidden` + `inert`（既不被读屏念到也点不到），关闭后焦点回到打开它的那个控件。ESC 走各弹窗自己的关闭按钮而不是硬改 class，因此原生返回键和 ESC 共用同一条关闭路径。32 处 `<div onclick>` 补 `role="button" tabindex="0"`，回车/空格由统一键盘处理激活；`<div>` 未换成 `<button>` 是刻意选择——这批控件的 CSS 全按 div 写，换标签的布局回归风险大于收益，键盘可达性与读屏播报已满足验收口径。

**表单与可读性**：17 个标签补 `for` 并逐个校验指向的 id 真实存在；`aria-pressed` 只保留在可切换的餐别上（瞬时动作按钮挂 pressed 会被念成"已按下"），且切换时同步更新；缺口图加 `role="img"` 与一行文字摘要（达标/未达/超支/未记录 + 目标值），不再依赖颜色；底导文字 9.5→11px、10.5→11.5px，主按钮 `min-height:44px`；样式表补 `prefers-reduced-motion` 与可见焦点框。

**完整日确认**：今日卡片补"今天记全了吗"入口，状态回读自服务端 `today_confirmed`，确认后可撤销，改动当天记录仍按原设计自动失效。服务端未升级、拿不到 `today` 时按钮禁用并显示"服务端未支持"——只把按钮灰着等于把故障洗成"没测"。

**缓存**：静态资源版本号从 mtime 改内容哈希，URL 带对哈希给 `public, max-age=31536000, immutable`，带错或不带给 `no-cache, must-revalidate`，HTML 保持短缓存。`version.json` 的更新说明改为现读 CHANGELOG 最新条目，去掉手写死字。

**就绪门禁**：`server.py` 的 `/health` 原来直接 `return "r131"`，`deploy.py` 又拿同一个死字比对——两边都硬编码时发错版本也照样判就绪。改为服务上报部署时落盘的 `release` + `source_revision`，部署脚本按本次提交的 SHA 对账，标签只作附带校验。

**会话兜底**：本机登录信息读不出来时清掉并提示重新登录，不再停在"看着像登录了却一格数据都没有"的页面。

## 5. 仍未覆盖（不写成通过）

1. **原生 `<button>` 的回车激活**：自动化按键通道只送非可信事件，浏览器默认激活不触发；我加的 `role=button` 因为代码里显式 `click()` 所以能验到，原生按钮这条需人工敲一次键盘。
2. **全新安装首屏**：验真正的首次安装必须 `pm clear`，而清数据会连带删掉机主本机未同步的离线草稿，属真实数据损失，故只测了冷启动。要补这条请先确认草稿已同步。
3. **放大字号后的可读性、键盘遮挡、拒权后的提醒说明**：脚本能证明"起得来、权限位变了"，排版是否难看必须看画面。
4. **整夜锁屏送达**：需跨夜观察厂商省电策略，本轮只验到闹钟登记与时区重排。
5. **相机真实拍摄并上传**：只证明 Intent 通道可用。
6. **Android 7/8/10/12/13+ 多机矩阵**：仍只有一台 Android 16。
7. **app.js 按模块拆分**：未做。实测四份核心文本原始 383KB / gzip 110KB，LCP 96ms，收益不足以支撑在无人值守时重构 4286 行单文件；`.btn-header-download` 高 25px 低于 44px 建议值，属非主操作，一并留档。
