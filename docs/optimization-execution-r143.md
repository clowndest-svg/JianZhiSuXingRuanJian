# r143 执行记录：接入可插拔在线模型，先解决「我哪知道每100g热量」

日期：2026-10-17。版本：versionCode 26 / 1.9.4。承接 r142。

## 1. 机主这句话是对的

「包装每100g热量 kcal」这一格，普通人根本不知道——那是给**手上有包装袋**的人填的，
却被放成了默认路径。他的要求：发食物和重量，让在线 AI 大概算一下；再看看还有什么能接。

## 2. 做了什么

**在线模型层（`app_modules/online_ai.py`，可插拔）**

- 配置只放服务器本地 `/opt/qingsu/ai-online.json`（`base_url`/`model`/`api_key`），
  已进 `.gitignore`；**强制 https**（密钥不走明文）；密钥不进仓库、不进日志、不进任何响应体。
- 新增 `POST /api/food/estimate`：菜名（可带克重）→ kcal + 三大宏量 + **它假设的克重和依据**。
  结果回填到「本餐热量」那格，人可以直接改。
- 硬校验，不合规一律不采纳：热量必须在 15~3000 kcal、克重必须给且不超 5000g、
  宏量 0~400g、依据里不许出现医疗话术；不按 JSON 返回就判"没给结果"。
- **没配置时不装作能用**：按钮文案改成「在线模型未接入」，
  `/api/ai/status` 出 `online_model=down` + `online_why`，接口回 `ok:false` 带原因，
  绝不回一个来路不明的数字。
- 在线模型同时接管两处原本由 0.5B 干的活：**开放闲聊**和**联网资料整理**。
  配更强的模型这两处一起变好，不用改代码。

**不依赖在线的那半（现在就能用）**

- 菜品表补复合菜名：`番茄鸡蛋肉汤面`、`肉汤面`、`汤面`、`卤蛋`、`蒸饺`、`砂锅` 等。
  以前这句只认出一个鸡蛋算 **75 kcal**，现在按整碗 **560 kcal** 走，且 `source=nutrition_kb`。
