# r173 / 2.2.12（57）引用回复、分页与缩略图、邮箱账号

本版修了一批体验问题：私信可引用回复；梗图与广场列表支持分页；社区图片改用缩略图并可缓存；修好改体重不更新与冷启动头像；邮箱登录/注册/找回与 60 秒限频。

## 改动

- 私信长按消息新增“引用”：输入区出现引用条，发送后气泡上方显示被引用内容（发送那一刻的快照，原消息之后撤回也不影响引用块）；点引用块可跳回原消息。
- 网络梗图搜索分页：App 滑到列表底部自动加载下一页，网页端保留“加载更多”按钮；中文梗图每页 12 条，来源池从 12 条扩到 60 条。广场列表滑到底自动加载（原本的游标分页保留）。
- 社区列表改用 480px 缩略图（`image_thumbs`），点开仍是原图；`/uploads` 响应从 `no-store` 改为可缓存 1 天（签名 URL 仍保证授权），重复浏览不再每次重下原图。
- 修复：改档案体重只写档案表、顶栏读“最新体重记录”，所以保存后仍显示旧体重；现在改体重会同步当天体重记录。
- 修复：冷启动时顶栏头像先闪成字母章；现在把上次头像缓存成 data URL 先画出来（头像仍走 15 分钟签名链接，不改成公开地址）。
- 邮箱账号：注册增加邮箱验证码（新客户端；邮件通道不可用时降级为旧流程并记日志）；登录支持“邮箱验证码”或“账号密码”；找回密码补齐“新密码 + 确认新密码”，个人中心直接可进；个人中心绑定邮箱与登录页发码都有 60 秒倒计时，服务端强制 60 秒冷却（10 分钟 4 次/IP、每小时 5 次/邮箱仍在）。
- 验证码邮件改为纯文本 + 简洁 HTML 双格式，补 `Date`/`Message-ID`/`Reply-To`/`X-Auto-Response-Suppress`，标题改为“轻塑验证码”。

## 关于“用 MinIO 会不会更快”和“能不能上 ES”

- 图片现在存在服务器磁盘 `/opt/qingsu/uploads`，由 FastAPI 以 15 分钟签名 URL 经 nginx 提供。慢的主因不是磁盘，而是**每次浏览都在重下 200~600KB 原图且响应被设成 `no-store`**。MinIO 只是换一种存法，带宽还是这台服务器的带宽，不会更快；要更快应该做的是缩略图 + 缓存（本版已做，列表流量降到约 1/4），真要到 CDN 级别再考虑对象存储 + CDN。
- 这台机器 4 核/3.6GB，已经跑着 qingsu、coturn、Directus（768MB）、llama（1.2GB）和 ASR（约 0.95GB）。Elasticsearch 至少还要 1~2GB 堆内存和一个常驻进程，会把内存挤爆，不建议上。站内搜索的量级用 SQLite 自带的 FTS5（trigram 分词，中文可用）就够，零新进程；将来量大了再考虑 Meilisearch（内存占用比 ES 小得多）或换 8GB 机器。

## 边界

- 邮件进不进收件箱还取决于 qq.com 的 SPF/DKIM/DMARC 与 Gmail 的域名信誉；本版只是把“看起来像群发”的写法（缺标准头、只有一行纯文本）改掉。要稳定进箱，建议换成带自有域名的发信服务（在 `mail.json` 里改 `from` 即可，不用改代码），并给该域名配 SPF/DKIM/DMARC。
- 注册的邮箱强校验只在邮件通道可用时生效；通道挂掉时降级为旧流程并写日志——不会因为邮件服务故障把新用户完全锁死。
- 社区配图列表用缩略图；聊天图片气泡仍用原图，头像仍走签名链接（没有改成可枚举的公开地址）。
- 真机（Android WebView 的键盘、头像冷启动、系统邮件客户端收信）仍未人工验，当前无 ADB 设备；Gmail 是否进垃圾箱无法在服务器侧自动判定。
