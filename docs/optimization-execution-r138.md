# r138 执行记录：手脚与骨长——"看着不对"的根因比形状更深

日期：2026-10-17。版本：versionCode 21 / 1.8.3。承接 r137。

## 1. 机主圈出来的两处

> 你看这个手脚正常吗，你就不能画精细一些吗，你的审美这么丑吗

截图是跪姿超人式（四点跪位），红框圈了①两只竖起来的"兔耳朵脚"、②支撑臂末端一团。
两处都是真 bug，但往下挖还有第三层，而且那层才是"看着不像人"的主因。

## 2. 三层根因

**① 脚的宽/厚系数写反（兔耳朵的直接原因）**
体块表里 `w` 是左右宽、`d` 是"脚底法线"方向（厚度）。我写成 `w: .95, d: 1.25`，
等于造了一只**比宽还厚**的脚，竖起来就是两片鱼鳍。改成 `w: 1.22, d: .52`（扁脚）
并给脚底加了足弓起伏。

**② 脚向规则一刀切**
r137 为了让站姿不"踮脚"，把脚向对小腿做了正交化。量过之后：
站姿小腿 upness=1.00 → 脚水平向前 ✓；但跪姿小腿是**躺平**的（upness=0.17），
强制垂直就把脚掰成朝天 90°。改成按小腿倾斜度混合：
小腿越竖直→脚越垂直于小腿（平踩地面）；小腿越躺平→脚越顺着小腿（跪姿脚背贴地）。
实测跪姿脚向从 90° 上翘变成 22° 后翘。

**③ 姿态表的骨长和 CesiumMan 对不上（最深层）**
量出来：姿态表要求大腿 0.366m，模型只有 0.304m——**腿短了 17%**。
所以四点跪位里"膝盖该落地"根本落不了，整个人悬空，看着就是"手脚不对"。
解法：一根骨的长度是由**它子骨的局部位移**实现的（子骨起点就是本骨终点关节），
所以按姿态表要求逐动作缩放子骨局部位移即可。修正量实测在 ±21% 内。
躯干那两根 `pelvis`/`spine` 共用同一对关节，缩放会重复计入，先不动。

另外补了两条小修：手原来是颗圆球（三轴太接近），改成巴掌（长>宽≫厚）；
新增"任何体块不许沉到地面以下"的通用规则——支撑手原来沿小臂方向继续往前戳，
半截穿进地垫里，看着像断掉的手。

## 3. 判据：这轮加的才是重点

**a. 5 条体块表的解剖朝向不变量**（`tests/legacy-backend.py`）
脚必须宽>厚、躯干必须宽>厚、手必须是巴掌、头颅竖轴最长、肘膝必须有关节帽。
标定：把坏值（`w .95 / d 1.25`、圆球手、去掉膝帽）塞回去 → **红 3 条，正是被圈出来的那两处**。

**b. 骨长校正的两条真机判据**（`DeviceSmokeTest`）
`lenScales` 必须非空且 `|k-1| ≤ 0.5`；`reach`（骨长残差）必须 ≤ 0.02。
标定：把 `LEN_CHILD` 整个关掉 → 真机当场红
`四肢骨长没有参与校正（表与模型比例脱节时这里会空）: lenScales:[]`。

**c. 一条差点骗过我的假判据**
我第一版 `reach` 量的是"解算关节的绝对坐标 vs 姿态目标绝对坐标"，得到 1.0~1.4m，
看着像"误差巨大"。其实姿态表以**身体中心**为原点、骨架站在模型自己的位置上，
那 0.9m 是平移不是误差。改成量**骨长残差**才对。
教训：一个数值判据在没被正反样本打过之前，永远不知道自己量的是什么。

**d. 截图证据从 2 张改成每个动作 1 张**
"兔耳朵脚"藏在第 4 个动作里，而我只截了 2 张——等于把最难看的那张跳过了。
现在 `ex3d-<i>.png` 逐个动作留档。
