## 1. 三条"看着是审美、其实是代码写错"的根因

这三条都不是"调调 CSS"的事，值得单独记：

1. **弹窗贴左上角**：根因在全局 `style.css:42` 的 `* { margin:0 }`。
   `<dialog>` 靠 UA 自带的 `margin-inline:auto` 居中，被这条 reset 抹掉了。
   所以判据"features.css 里有没有写居中"根本测不到——它写了，只是被覆盖了。
   修法：`.tool-dialog{position:fixed;inset:0;margin:auto}` 显式写回，
   **真机上量左右留白是否相等**（`|left-(innerWidth-right)|<=4`），不看 CSS 写没写。
2. **聊天气泡不能复制**：同一个 reset 里的 `* { user-select:none }` 把气泡、正文、评论一起锁死。
   修法是给"要读的东西"逐个放开，而不是全局改回来（全局那条是防长按误选的）。
3. **统计格四个数全是 `NaN`**：接口给的是对的（`likes_received:1`），渲染层把
   `[key, label, value]` 三元组的下标写串，取成了 `Number(label)`。
   **两处各写一遍，所以同时坏两遍**——抽成 `qsStatsHTML()` 一个纯函数，
   判据可以直接在 vm 里跑它，不依赖 DOM 就能钉"数字位上是数字"。

## 2. 统一了什么，没统一什么

动作按钮一律胶囊圆角；次按钮浅绿底 `#ECFDF5` + 深绿字，悬停深绿底白字；
主按钮保持深绿渐变，悬停更深。**主次权重必须还在**（上一轮刚因为"五颗一样的绿描边胶囊"被骂过），
所以统一的是形状与反馈，不是把两档压成一档。

踩到的坑：同时挂 `td-btn` 和 `td-btn-quiet` 的元素（搜索、私信、看更早的消息）
被后写的 `.td-btn` 渐变盖回主按钮权重——主页上「关注」「私信」又变成两颗一样的绿胶囊。
补了 `.td-btn.td-btn-quiet` 提权。

**没参与统一的**：`mode-btn` / `td-seg` / `plan-tab-btn` / `gender-mini-btn` / `dining-mode-btn`。
它们是"当前选中哪一项"的指示器，不是动作按钮，压成绿胶囊会丢掉选中态。

新增一个覆盖式页面层（`#page-layer`：固定顶栏带返回 + 可滚正文 + 可选固定底栏），
用户主页、帖子详情、私信会话、统计明细四类全部搬进去。栈支持二级跳
（帖子 → 用户主页 → 私信），返回一级一级退，`closePage()` 返回布尔值给硬件返回键用。

看图又抓出两个自己造的 bug：
- **换页没清顶栏右侧槽位**：「关注 0」这一页头上挂着一颗上一页遗留的「私信」按钮，
  点了没有上下文。`qsRenderTop` 里统一清空 + 补判据。
- **聊天消息贴顶**：内容不足一屏时气泡孤零零在顶上。改成贴底。

## 4. 聊天补齐

- **撤回**：`POST /api/chat/recall`，只能撤自己的、5 分钟内。
  **是打标记不是删行**——两端都还能看到"谁撤回了一条消息"，但 `_message_dict` 按标记把正文抹掉，
  历史接口不再回原话。会话摘要如果正是这一句，跟着改成"（已撤回）"。
- **复制**：右键（桌面）或长按（手机）出菜单。
- **气泡装扮**：只改自己这一侧，存 `community_profile.bubble_theme`，白名单五档，脏值 400。
- **列表实时刷新**：发送/收到/撤回三处共用 `bumpConversation()`。
  原来只更新了聊天窗，没动会话摘要，所以"要刷新才展示最新消息"。

## 5. 属地：修的时候顺手抓到一个反向 bug

原来只在发帖时解析 IP，评论根本不写档案——而界面上那句话本来写的是
"发一次帖子或评论就会带上"。现在注册、登录、发帖、评论四处都会落，
并且**解析不出来的那一次不再把已有属地洗掉**（原来从代理后面发一条帖，主页属地就变回"未知"）。

**一个差点误判的现场**：真机截图上"阿毛"显示属地未知，看着像属地功能坏了。
查库发现库里那一轮的两个账号都是 `湖南`——截图点开的是**上一轮遗留的同名夹具**（轻塑号对不上）。
搜索按昵称命中了历史账号。修法不是改产品，是改测试：夹具改成按本轮的轻塑号精确找人。
（顺带说明：`region_seen_at` 这种"什么时候看到的"字段在这种对账里非常有用。）

## 6. 判据与真机

- 后端 **495**、前端 **283**、集成 **44**、AI 契约 **6**（上一版 471 / 265 / 37 / 6，净增 48 条）。
- **新增了一道最便宜也最该早就有的门**：界面绑的每个 `onclick/onchange/...` 函数名
  必须能解析到已定义的函数。上一轮清单里的 P0 第 1 条（「全部标为已读」绑了个不存在的函数，
  未读红点永远消不掉）就是四套判据全绿漏过去的——这条静态判据能永久堵死这一类。
  现在实测：125 个绑定名，0 个悬空。
- 变异标定共 10 次，每次只红对应那一条：
  死按钮 / 弹窗不居中 / 登录不落属地 / 撤回不限本人 / 次按钮回白板 /
  统计格下标写串 / 未读计数拿掉 / 复制退回拼进 onclick / 撤回窗口写死 / 气泡不标撤回。
  其中"复制退回拼进 onclick"同时被"features.js 加载不抛异常"挡下——
  **正是它当初的坏法**（我这一轮真的又踩了一次，写出了一个语法错的按钮，被这条拦住的）。
- 真机（MuMu）5 个用例一次 instrument 全过，**94.0 秒**。
  社区那条现在覆盖：发帖 → 点赞 → 评论（整页 + 底部输入框）→ 按轻塑号找人 →
  整页主页（复制按钮带真值、属地与接口一致）→ 真 WebSocket 发私信 →
  **发出去后会话摘要立刻更新** → 右键撤回（撤完原话不再显示）→
  返回一级一级退 → 统计格是 BUTTON 且能点进明细 → 同城页签 → 弹窗居中度量。
- **本轮修出来的两个真机用例自身的坑**（都记进 memory 了）：
  ① `InputStream.readAllBytes()` 在 Android 上不存在，夹具读响应要手写循环；
  ② 设了 `MSYS2_ARG_CONV_EXCL='*'` 之后 `~/.android/debug.keystore` 也不展开了，
     签名器直接报找不到文件——给 Windows 原生程序的路径一律写绝对路径。

## 9. 这一轮没做到 / 别当成已通过

1. **同城只到省**，且用的是发帖/登录时那一次的 IP。人在省内换城市不会变，出省才会。
2. **撤回是 5 分钟窗口**，超了就撤不掉（服务端硬判，前端只是不显示按钮）。
   撤回不删行，数据库里正文还在——这是"两端都要能看到撤回了一条消息"和
   "记录不可信"之间选的折中，**不等于对方没读到过**。
3. **气泡装扮只改自己**，对方那边永远是他自己选的颜色。别当情侣装扮宣传。
4. **私信仍然没有离线推送**：对方不在线时消息只躺在库里，下次进 App 才看得到。
   WS 也仍是单进程广播（现役 unit 没有 `--workers`）。
5. **`markNoticesRead` 这次接上了，但通知仍然不能翻页**——只读前 30 条，
   服务端给的 `next_cursor` 前端没用。
6. **上一轮清单里那些没动的**：反馈/举报仍然没有后台（`UPDATE feedback` 依然 0 命中，
   `content_reports` 依然只写不读）、账号注销仍然没有、AI 定制菜谱仍然没有、
   SMTP 仍然等机主给账号、图片仍然只有归属校验没有内容审核。
7. **真机仍然只在 MuMu 上跑过**，真实 vivo 一台证据都没有；桌面档只量过顶栏与这几张新页，
   老的 7 个页面窄屏仍然零覆盖。
