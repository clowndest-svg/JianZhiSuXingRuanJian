# r176 / 2.2.15（60）目标身材 × 训练场景联动

本版把“目标身材”和“形体训练计划场景”从两个各存各的字段，变成共同生成同一份训练计划的两个输入。

## 两者是什么关系

- **目标身材**决定练哪里、吃多少：8 种身形分别对应臀腹/肩背/护膝等训练重点，也对应服务端的热量缺口与蛋白/碳水/脂肪比例。
- **训练场景**只决定怎么练：同一份目标在居家、弹力带、户外、健身房四种条件下，会换成不同器械版本的动作、组次、默认时长和有氧方式；**不改热量目标**。
- 两个选择组合后生成 4 个动作的主课、默认计时和打卡计划名；任何一边变化都会重新生成。

## 改动

- 新增 8 种身材 × 4 种场景的训练计划矩阵：每个组合都有 4 个动作、组次、建议时长和器械要求；场景替换动作有独立要点与常见错误，不再只换名字。
- 训练页顶部新增“目标身材 × 训练场景”卡片和场景切换：可直接在训练页切居家/弹力带/户外/健身房，动作、默认时长、有氧安排立即变化，并写回服务端；失败会退回原场景。
- 档案弹窗的场景选择会实时预览组合结果（目标、器械、主课时长、热量口径），并说明“身材决定热量，场景不改热量预算”。
- 计时器默认值改为当前计划的主课时长；“重置主课 / 有氧加练”按钮按场景显示对应分钟数；实时燃脂和训练打卡按场景估算，打卡记录实际计划名。
- 修复档案保存的并发覆盖：先选场景再保存身高体重时，档案写入串行执行，旧请求不会把新身高体重覆盖回去；仪表盘/图表的过期响应也会被丢弃。
- 服务端校验 `goal_type` 与 `scene` 取值，非法值不再静默入库；旧账号的 `tone/loss/muscle/tight` 继续兼容。
