# r186 / 2.2.25（70）：服务器时间与轻量私聊优化

状态：本机验收与正式签名打包通过，等待完整CI和生产发布回填。2026-10-24，Asia/Taipei。

私聊使用服务器保存的消息时间，居中显示 `YYYY-MM-DD HH:mm:ss`。首次消息、跨天、间隔达到5分钟或时间发生回退时显示分组时间；每条消息仍包含可访问的精确时间，长按/右击菜单也会展示该条的发送年月日时分秒。完整时间放在气泡外，不再撑高短消息。默认气泡、装扮、表情、图片和语音的发送/已读状态统一在气泡外；撤回记录仍参与时间分组。

实测主服务环境为 `TZ=Asia/Taipei`，即UTC+08。历史 `created_at` 字段原样保留，响应新增 `created_at_iso` 明确偏移；浏览器按同一时区显示，不依赖电脑/手机设置的时区，也不以本地当前时间推算“刚刚”。在洛杉矶浏览器时区下验证了旧格式、带Z的UTC时间、跨天和秒级显示；未知时间不会使用当前时间补造。没有改写历史时间、数据库结构或其他模块的时间含义。

按服务器实测选择优化：4逻辑核、3655MiB内存，快照可用1490.6MiB、1分钟负载0.11、磁盘剩余约25.4GiB；不是持续容量或高并发认证。现有数据库只有2个真实用户、26条消息，本轮没有据此推断百万消息容量，也未进行生产压测。没有新增服务、worker、队列或数据库，保持schema13及现有Redis连接池。

会话列表原先按联系人逐条读取头像、预览、未读、拉黑和在线状态。现在最多100个会话合并为2条SQL，未读聚合只覆盖本页会话，在线状态合并为1次Redis MGET；Redis故障仍保留原有内存回退。隔离的30会话夹具实测为2条SQL、1次MGET，删除可见性、未读数、头像缺失、拉黑和在线状态通过。继续使用原有消息索引，无需建额外索引或迁移。

连续消息造成的会话列表/统计刷新合并到500ms内一轮；页面在后台时不发此类刷新，回到前台补一次。真实Chromium中100个刷新信号只发1次会话列表GET和1次统计GET；后台100个信号不发请求，恢复前台再补这一对请求。没有新增定时轮询，消息正文仍由实时连接立即显示。

修复HTTP历史快照覆盖同时到达的WebSocket消息：按ID合并请求发出后到达的新消息，并保留更新的编辑版本、撤回和已读状态；旧刷新、分页、搜索跳转及会话切换的迟到响应按代次失效。刷新失败保留已有消息，不清空正在看的记录。撤回按钮的时限判断改用明确时区的服务器时间；服务端仍负责最终权限校验。历史页面和数组继续最多120条，分页每页30条，搜索上下文最多41条。

本机通过：623条旧后端、355条旧前端、10组历史API、16组历史真实浏览器检查、34组既有聊天媒体流程、20气泡/20背景整体验证、26项资源预算，以及DM状态/转写竞争契约。完整CI与生产结果以之后的实际回填为准，不把本机通过当作线上证明。实体Android安装、系统手势和双实体设备通话未测。既有的独立异地备份缺口保持不变。
