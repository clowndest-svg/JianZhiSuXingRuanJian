# r177 / 2.2.16（61）修「档案保存了体重，顶栏还是旧数字」

## 你截图里的现象与真实数据

图一档案是 138 斤，图二顶栏是 140 斤。服务器上的真实数据：

| 位置 | 值 | 时间 |
| --- | --- | --- |
| 档案 `profiles.weight_jin` | 138 | 2026-10-22 09:39（你那次保存确实写进去了） |
| 最新称重记录 `weight_logs` | 140 | 2026-10-15 18:20 |

顶栏读的是**最近一次称重记录**，不是档案字段，所以它一直显示 10-15 的 140；身高读的是档案字段，所以"改身高会变、改体重不变"。

## 为什么"再保存几次也没用"

r173 加过一条补写逻辑：保存档案体重时顺手写今天这条称重记录。但它的触发条件写成了「**档案里的数值发生变化**」。

你的档案早在补写逻辑上线之前就已经是 138 了，之后每次保存都是"138 → 138，没变化"，于是永远不补写；那条 10-15 的 140 就一直赢。**分叉是历史留下的，条件却只看这一次有没有变**——这就是根因，不是你操作错，也不是缓存。

## 改动

- 补写判据从"档案值变了没"改成"**最新称重记录 ≠ 刚保存的体重**"：只要不一致就把今天这条补上，历史记录原样保留（不会抹掉 10-15 的 140）。数值已经一致时不重复插行。
- 档案弹窗的「当前体重」改为预填**顶栏显示的那个数**。之前弹窗读档案、顶栏读记录，两处可以各显示一个数字，用户照着改完还是对不上。
- 服务端仍按同一口径校验 `goal_type` / `scene`（r176 引入），本轮未改。
